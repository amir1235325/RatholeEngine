# طراحی: بازنویسی UI هاب + ریورس‌پروکسی غیرتونلی

تاریخ: ۲۰۲۶-۰۷-۲۶ · وضعیت: تأییدشده برای اجرا

## مسئله

### ۱) دکمه‌های حالت گمراه‌کننده‌اند (باگ، نه فقط زشتی)

روی نود، **پنج دستور همگی یک متغیر واحد را می‌نویسند** (`ratholenode`، `env_set TUNNEL`):

| دستور | مقدار `TUNNEL` |
|---|---|
| `kcp on` | `kcp` |
| `plain on` | `plain` |
| `noise on` | `noise` |
| `backhaul on` | `backhaul` |
| هر `... off` | `ws` |

یعنی حاملِ تونلِ هر نود **ذاتاً انحصاری** است. ولی UI فعلی پنج جفت دکمه‌ی مستقل on/off نشان می‌دهد؛ کاربر تصور می‌کند می‌تواند ترکیبشان کند در حالی که **آخرین دستور بی‌صدا برنده می‌شود**. هیچ بازخوردی هم نمی‌گیرد.

### ۲) عوض‌کردن حامل دو عمل هماهنگ لازم دارد

برای `noise` و `backhaul` باید هم سمت ایران فعال شود (`ratholectl <mode> on` + `ratholectl <mode> node <name> on`) و هم سمت نود (`ratholenode <mode> on ...`). امروز کاربر هر دو را دستی می‌زند و به‌سادگی ناهماهنگ می‌شوند — که علامتش تونلِ بالا‌نیامده است بدون پیام روشن.

### ۳) تنظیمات ناقص

بک‌اند (`build_iran_cmd` → `set_config`) از قبل `fake-port`، `sub-port` و `control-port` را می‌پذیرد، ولی UI فقط `domain`، `fullchain` و `key` را نشان می‌دهد. یعنی قابلیت هست، فقط سطحش نیست.

### ۴) ساختار کد مانع توسعه است

`hub.py` = ۳۲۱۰ خط، که ~۱۶۰۰ خطش HTML/CSS/JS/i18n داخل یک رشته‌ی پایتون است. ویرایش JS یعنی اسکرول در رشته‌ی خام بدون هایلایت و بدون لینت. لیست‌سفید امنیتی (`build_*_cmd`) هم وسط همین حجم گم است، در حالی که حساس‌ترین بخش کل پروژه است.

## تصمیم‌ها

### الف) مدل دو سطحی

UI باید تفاوت نقش ایران و نود را منعکس کند — چون CLI هم همین را می‌کند:

- **سرور ایران — «چه حامل‌هایی در دسترس‌اند»:** هر حامل یک listener/core مستقل روی ایران دارد (kcp، plain، noise، backhaul). اینها واقعاً مستقل‌اند و هرکدام سوییچ خودش را می‌گیرد.
- **نود — «این نود از کدام حامل استفاده می‌کند»:** **یک `select` انحصاری** با پنج گزینه: `ws` (پیش‌فرض) / `kcp` / `plain` / `noise` / `backhaul`.

### ب) عمل هدایت‌شده‌ی «تعیین حامل»

انتخاب حامل برای یک نود یک عمل واحد می‌شود که:

1. بررسی می‌کند سمت ایران آن حامل فعال است؛ اگر نه، اول فعالش می‌کند.
2. برای `noise`/`backhaul`، نود را سمت ایران به آن مسیر می‌برد (`<mode> node <name> on`).
3. سمت نود حامل را ست می‌کند، با پارامترهای صحیح که **خودکار از سرور ایران گرفته می‌شوند** (همان الگوی `noiseconnect`/`backhaulconnect`).
4. اگر نود قبلاً روی حامل دیگری بود، سمت ایران از آن مسیر خارجش می‌کند تا state ناسازگار نماند.

### ج) دسته‌بندی درست

- **حامل‌ها** (انحصاری روی نود): ws / kcp / plain / noise / backhaul
- **ورودی‌ها (ingress)**: `direct` — این حاملِ تونل نیست، یک درگاه ورودی کاربر است. بخش جدا.
- **اتوماسیون**: `adaptive`، `watchdog` — مستقل، سوییچ ساده.

### د) صفحه‌ی تنظیمات

همه‌ی پورت‌ها یک‌جا. آن‌هایی که `ratholectl set` پشتیبانی می‌کند (`fake-port`, `sub-port`, `control-port`) مستقیم ویرایش‌شدنی‌اند؛ بقیه (internal، hub، پورت هر حامل) نمایش داده می‌شوند و به تنظیم مربوط به خودشان لینک می‌خورند. پیش از ارسال، تداخل پورت هشدار داده می‌شود.

### ه) ساختار کد

```
rathole-manager/ratholehub/
  hub.py        # ورودی، روتر، وضعیت، SSH، پارسرها
  hubcmds.py    # امنیتی: RE_*، build_iran_cmd، build_node_cmd، WRITE_ACTIONS
  ui/
    index.html
    app.css
    app.js
    i18n.fa.json
    i18n.en.json
```

قید پروژه **«فقط stdlib، بدون pip»** است — نه «تک‌فایل». این قید حفظ می‌شود. فایل‌های `ui/` از دیسک سرو می‌شوند با **لیست‌سفید نام فایل** (نه پیوستن مسیر) تا path traversal ممکن نباشد.

هزینه: `install-hub.sh` باید درخت را کپی کند نه یک فایل. `package.sh` چون کل `rathole-manager/` را با `zip -r` می‌بندد، خودکار پوشش می‌دهد.

## ریورس‌پروکسی غیرتونلی

`ratholectl proxy add <name> <upstream>` یک `location /<name>/` در nginx می‌سازد که به یک upstream دلخواه proxy می‌کند — برای تونل‌ها یا سرویس‌های کاستومی که rathole مدیریتشان نمی‌کند.

- state: `.proxies[]` با `{name, upstream}`.
- **فضای‌نام مشترک با نودها:** هر دو در `map $uri` می‌نشینند، پس نام تکراری باید رد شود (هر دو جهت).
- upstream فقط `http://host:port` یا `https://host:port` — بدون مسیر، بدون متاکاراکتر شل، با regex اعتبارسنجی می‌شود.
- در هاب: اکشن‌های `proxy_add`/`proxy_rm`/`proxy_ls` با argv-list و regex، مثل بقیه.

**امنیت:** این قابلیت به اپراتور اجازه می‌دهد nginx را به میزبان دلخواه اشاره دهد. اپراتور-کنترل است و ورودی با regex محدود می‌شود، ولی باید در مستندات صریح باشد که upstream اعتماد‌شده فرض می‌شود.

## معیار پذیرش

- انتخاب حامل برای یک نود از هاب، هر دو سمت را هماهنگ می‌کند و وضعیت نهایی در `ratholectl backhaul/noise status` و `ratholenode status` یکی است.
- انتخاب حامل جدید، حامل قبلی را سمت ایران پاک می‌کند (state ناسازگار نمی‌ماند).
- `fake-port`/`sub-port`/`control-port` از UI قابل تغییرند.
- `proxy add` با نام یک نود موجود رد می‌شود و برعکس.
- `hub.py` بدون pip بالا می‌آید؛ `RATHOLEHUB_MOCK=1` مثل قبل کار می‌کند.
- تمام گیت‌های CI (`bash -n`، `py_compile`، `shellcheck --severity=error`) پاس.
